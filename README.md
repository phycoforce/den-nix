# Den Desktop

Den-based NixOS flake for the `temperantia` desktop and the `aaron` user:
CachyOS kernel, Niri + Noctalia Shell, NVIDIA open kernel module (alongside
AMDGPU), SDDM, Home Manager, and disko-managed storage. `flake.nix` is
generated by `flake-file` (`nix run .#write-flake`); the real configuration
lives under `modules/`.

## Install From A Fresh NixOS ISO

Boot a recent NixOS installer ISO in UEFI mode with Secure Boot disabled
(nothing here signs boot files). Get network access (`nmtui` on the minimal
ISO), then become root with `sudo -i`.

Verify disks before the destructive step:

```sh
lsblk -f
ls -l /dev/disk/by-id
```

disko wipes only `mainDisk`
(`/dev/disk/by-id/nvme-eui.000000000000000100a0752448c2bd18`). The existing
Btrfs disk labeled `SSD2` is outside disko and must not be formatted. If the
OS disk shows a different stable by-id path, edit `mainDisk` in
`modules/_nixos/storage.nix` after cloning — never use an unstable kernel
name like `/dev/nvme0n1`.

Clone, partition, and install:

```sh
nix --extra-experimental-features "nix-command flakes" shell nixpkgs#git -c \
  git clone https://github.com/phycoforce/den-nix /tmp/den-nix

nix --extra-experimental-features "nix-command flakes" --accept-flake-config \
  run github:nix-community/disko/latest -- \
  --mode destroy,format,mount \
  --flake /tmp/den-nix#temperantia

mkdir -p /mnt/etc/nixos
cp -a /tmp/den-nix /mnt/etc/nixos/den-desktop

nixos-install \
  --flake /mnt/etc/nixos/den-desktop#temperantia \
  --option extra-experimental-features "nix-command flakes" \
  --option accept-flake-config true \
  --option extra-substituters "https://attic.xuyh0120.win/lantian https://nix-community.cachix.org" \
  --option extra-trusted-public-keys "lantian:EeAUQ+W+6r7EtwnmYjeVwx5kOGEBpjlBfPlzGlTNvHc= nix-community.cachix.org-1:mB9FSh9qf2dCimDSUo8Zy7bkq5CX+/rkCWyvRCYg3Fs="

nixos-enter --root /mnt -c 'passwd aaron'
reboot
```

Set a root password when `nixos-install` prompts for one.

After first login (SDDM, `niri` session), store the 1Password service-account
token so OpNix can render the agent MCP secrets during Home Manager
activation:

```sh
mkdir -p ~/.config/opnix
nix run github:brizzbuzz/opnix -- token set -path ~/.config/opnix/token
chmod 600 ~/.config/opnix/token
```

The service account needs read access to
`op://kubernetes/cluster_secrets/SECRET_DOMAIN` and
`op://kubernetes/memini/MEMINI_API_KEY`. Never commit the token or the
generated files under `~/.config/homeops-mcp/`.

## Rebuilds

Day-to-day rebuilds go through `just`, which runs the plan-gate first — it
refuses a lock whose non-trivial derivations no substituter can serve:

```sh
just sync && just switch    # adopt the lock the daily CI updater already proved
just update && just switch  # bump inputs locally, newer than the bot
just switch                 # rebuild the current lock (repo checkout)
just switch-installed       # same, from /etc/nixos/den-desktop
```

For kernel or NVIDIA driver changes use `just boot` and reboot: a live switch
can activate new NVIDIA userspace under the still-running old kernel and break
`nvidia-persistenced.service` until the next boot.

When `just` is unavailable (e.g. the first rebuild after install), the raw,
ungated command — the explicit cache options matter until a generation
carrying the cache settings has been built:

```sh
sudo nixos-rebuild switch \
  --flake /etc/nixos/den-desktop#temperantia \
  --option accept-flake-config true \
  --option extra-substituters "https://attic.xuyh0120.win/lantian https://nix-community.cachix.org" \
  --option extra-trusted-public-keys "lantian:EeAUQ+W+6r7EtwnmYjeVwx5kOGEBpjlBfPlzGlTNvHc= nix-community.cachix.org-1:mB9FSh9qf2dCimDSUo8Zy7bkq5CX+/rkCWyvRCYg3Fs="
```

## Troubleshooting

If an update is held back, `just status` shows on one screen whether the
problem is upstream, the binary cache, or local tooling; `just hydra-check
<pkg>` distinguishes "Hydra is merely behind" from "broken upstream".

Health checks after a rebuild or boot:

```sh
uname -r                          # CachyOS kernel
systemctl status scx.service display-manager.service home-manager-aaron.service
nvidia-smi
findmnt /mnt/SSD2
pgrep -a 'niri|noctalia|xwayland-satellite'
```

Secrets and agent CLIs: the OpNix token and generated secret files should be
`aaron:aaron 600`:

```sh
stat -c '%U:%G %a %n' ~/.config/opnix/token \
  ~/.config/homeops-mcp/secret-domain ~/.config/homeops-mcp/memini-api-key
```

If 1Password is unreachable during a rebuild, Home Manager keeps using the
existing secret files; only a fresh bootstrap requires 1Password to be
reachable. Claude Code activation steps no-op until `api.anthropic.com`
resolves, so agent CLI setup may only complete on a rebuild after the network
is up.
